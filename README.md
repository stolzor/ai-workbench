# Portable OpenCode workbench

Переносимая конфигурация OpenCode V2 и `oh-my-opencode-slim` без секретов,
сессий, истории, логов и кэшей.

Node.js и OpenCode закреплены в `mise.toml`. Установите их один раз:

```sh
cd ~/ai-workbench
mise trust
mise install
```

После установки `postinstall`-хук автоматически подключает конфиги OpenCode
и Slim из репозитория и добавляет активацию mise в настройки zsh/bash, если
её ещё нет. Конфликтующие конфиги (JSON и JSONC) сохраняются рядом как
`.bak.<дата>`; весь каталог OpenCode не заменяется. Повторный `mise install`
безопасен и повторяет настройку, даже если инструменты уже установлены.

Используется `${XDG_CONFIG_HOME:-$HOME/.config}/opencode`; для zsh учитывается
`ZDOTDIR`. Другие shell автоматически не настраиваются: скрипт выведет
подсказку. Плагин загружается OpenCode при запуске, авторизация не переносится.
После изменения `mise.toml` может потребоваться повторный `mise trust`.

### macOS: активация mise

Установщик не может изменить окружение уже открытого терминала. После первой
установки откройте новый терминал или для стандартного macOS shell zsh выполните:

```sh
source "${ZDOTDIR:-$HOME}/.zshrc"
opencode --version
```

Если терминал всё ещё пишет `command not found: opencode`, проверьте из
каталога репозитория:

```sh
mise exec -- opencode --version
```

Если версия выводится, проблема в активации mise. При отключённых хуках
добавьте в `~/.zshrc` следующую строку (если её ещё нет):

```sh
eval "$(mise activate zsh)"
```

Примените настройки shell и проверьте команду:

```sh
source ~/.zshrc
opencode --version
```

Это инструкция для zsh — стандартного shell macOS. Для другого shell нужна
соответствующая команда активации mise.

## Текущая конфигурация

- Slim закреплён на версии `3.0.6`; `autoUpdate` отключён.
- Основной доступ: официальный вход OpenAI через ChatGPT Plus/Pro.
- Orchestrator и Fixer: `openai/gpt-6.1-sol`.
- Explorer и Designer: `openai/gpt-6-luna`.
- Oracle: `openai/gpt-6.1-sol`, вызывается по риску, а не после каждой правки.
- Не более двух одновременно работающих фоновых задач.
- `wallClockTimeoutMs=1800000` ограничивает отдельного фонового исполнителя,
  а не всю сессию и не расходы.
- Автоматический fallback, Council injection, Marketplace tools, Interview,
  Companion и multiplexer отключены.
- Shell-команды требуют подтверждения OpenCode.

## Запуск

Из каталога нужного проекта:

```sh
~/ai-workbench/bin/oc
```

Wrapper читает версии из `mise.toml`, запускает OpenCode через `mise exec`,
не меняет текущий каталог и передаёт все аргументы OpenCode.
Web search по умолчанию выключен. Для явного включения Exa на один запуск:

```sh
~/ai-workbench/bin/oc --web
```

## Вход и проверка

Авторизация хранится отдельно и не переносится. При необходимости запустите
OpenCode и выполните `/connect`, выберите OpenAI и официальный вход ChatGPT.
Не помещайте токены в этот репозиторий.

Проверка без модельных запросов:

```sh
opencode plugin list
opencode models
mise exec -- npx oh-my-opencode-slim@3.0.6 doctor
```

`ping all agents` обращается к моделям и расходует квоту; запускайте его только
осознанно. На OpenCode V2 команды `opencode models --refresh` нет.

## Перенос на вторую машину

1. Установите mise версии из `versions.txt` или новее. Bun не обязателен.
2. Клонируйте приватный репозиторий как `~/ai-workbench`, затем установите
   закреплённые инструменты:

   ```sh
   cd ~/ai-workbench
   mise trust
   mise install
   ```

3. Хук установки создаст ссылки на два управляемых конфига, сохранив
   существующие конфликты в резервные копии, и настроит активацию mise.
   Репозиторий может находиться и в другом каталоге: ссылки используют его
   фактический абсолютный путь. Не удаляйте и не перемещайте его после настройки;
   после перемещения повторите `mise trust` и `mise install` из нового каталога.
4. Откройте новый терминал или выполните команду `.`, которую напечатал
   установщик. Если хуки отключены, настройку можно запустить явно:

   ```sh
   sh ~/ai-workbench/bin/setup
   ```

5. Запустите `~/ai-workbench/bin/oc` и убедитесь, что pinned-плагин
   `oh-my-opencode-slim@3.0.6` загрузился.
   Один перенос JSON не переносит установленный пакет или кэш.
6. Авторизуйте OpenAI заново через `/connect` на второй машине.
7. Выполните `opencode plugin list`, `opencode models` и doctor.
8. Запускайте `~/ai-workbench/bin/oc` из нужного проекта.

### OpenCode запускается, но оркестратора нет

Оркестратор поставляется плагином `oh-my-opencode-slim`, а не самим OpenCode.
Если настройки не подключились (например, хуки были отключены), повторите
`mise install` из репозитория либо выполните `sh ~/ai-workbench/bin/setup`.
Запустите `~/ai-workbench/bin/oc` и выполните `/reload` в OpenCode.
Проверьте загрузку плагина и ссылки:

```sh
opencode plugin list
ls -l "${XDG_CONFIG_HOME:-$HOME/.config}/opencode/"
```

В списке должен присутствовать `oh-my-opencode-slim@3.0.6`, а две ссылки должны
указывать на существующие файлы этого репозитория. Если проблема осталась,
сохраните вывод этих команд для диагностики.

## OpenRouter как независимый резерв

Резерв намеренно не активирован и баланс не пополнялся. Для подключения
запустите `/connect`, выберите OpenRouter и введите ключ локально, затем
получите реальные модели через `/models` или `opencode models`. Только после
этого добавляйте отдельный preset с фактическими ID. Сначала задайте лимит
расходов на стороне провайдера; concurrency и timeout денежным лимитом не
являются.

## Обновление

1. Проверьте release notes и схему новой версии.
2. Создайте датированные копии двух конфигов.
3. Для OpenCode/Node измените версии в `mise.toml`, выполните `mise install`
   и обновите `versions.txt`. Для Slim замените точную версию одновременно в
   `config/opencode.jsonc`, `$schema` Slim и `versions.txt`.
4. Выполните reload и doctor, затем минимальный smoke test.
5. Проверьте, что ссылки не заменены обычными файлами:

   ```sh
   test -L ~/.config/opencode/opencode.jsonc
   test -L ~/.config/opencode/oh-my-opencode-slim.jsonc
   ```

Не используйте `--reset` без отдельного решения. Изменение preset по умолчанию
не меняет уже привязанную V2-сессию; примените `/preset <name>` к текущей
сессии или начните новую.

## Откат

Удалите только две управляемые ссылки и восстановите датированные копии, если
они были созданы. Затем выполните `opencode reload`. Если сервис неисправен,
а не просто перечитывает конфиг, используйте `opencode service restart`.

Чтобы отменить активацию mise, удалите добавленные установщиком комментарий
и строку `eval` из файла shell, указанного при установке. Хук снова подключит
настройки при следующем `mise install`; для установки без настройки используйте
`mise --no-hooks install`.

Синхронизация этих файлов не переносит авторизацию, активные сессии, историю,
логи, базы данных или кэши.

## Проверка установщика

```sh
sh -n bin/setup
python3 -m unittest discover -s tests -v
```

Тесты используют временные домашние каталоги, не меняют реальные пользовательские
настройки и не обращаются к моделям. Поведение macOS проверяется имитацией
`uname`; отдельная проверка на настоящем Mac остаётся полезной.

## Git

Перед staging всегда проверьте `git status` и `git diff --cached`, а также
отсутствие секретов. `.gitignore` — только дополнительная защита. Инициализация,
commit, создание private remote и push выполняются отдельно и только явно.
